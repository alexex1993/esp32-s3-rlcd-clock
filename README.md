# Настольные часы на ESP32-S3-RLCD-4.2

Прошивка для платы **Waveshare ESP32-S3-RLCD-4.2** (SKU 33298 / 33507) с 4,2-дюймовым отражающим монохромным экраном на контроллере ST7305. Плата работает как настольные часы с четырьмя экранами:

1. **Часы.** Время крупными цифрами, дата, погода на улице (температура, влажность, давление, УФ-индекс и качество воздуха), прогноз на 12 часов, время заката и заряд аккумулятора 18650.
2. **«В МИРЕ».** Заголовки новостей на русском языке с Русской службы BBC и DW. Загружаются, когда вы открываете экран.
3. **«ПЕЙДЖЕР».** Сообщения, которые пишут вашему Telegram-боту. Пока экран открыт, соединение не закрывается: новое сообщение появляется примерно через секунду, а динамик издаёт короткий сигнал. На каждое прочитанное сообщение бот ставит реакцию 👀, так что отправитель видит в чате, что часы его получили.
4. **«КОМПЬЮТЕР».** Состояние игрового ПК в реальном времени: температура, загрузка, частота и потребление видеокарты; температура, общая загрузка и потребление процессора; частота видеопамяти; FPS, а под ним график FPS за последние полторы минуты. Данные приходят по локальной сети от программы [rtss_api](rtss_api/) на ПК и обновляются два раза в секунду.

Репозиторий содержит обе половины проекта: прошивку для платы и серверную часть для экрана «КОМПЬЮТЕР» — программу [rtss_api](rtss_api/) для Windows, которая отдаёт часам телеметрию игрового ПК. Без неё экран «КОМПЬЮТЕР» работать не будет, поэтому её исходники лежат здесь же, в каталоге [`rtss_api/`](rtss_api/).

Экраны переключаются кнопкой **KEY**. Подсветки у экрана нет: картинка держится без питания, а видно её при обычном освещении, как бумагу. Все надписи на экране по-русски.

Каждый из четырёх экранов — **отдельный режим, который включается и выключается при сборке** (раздел [«Режимы»](#режимы-какие-экраны-собирать)). По умолчанию включены все четыре; можно собрать прошивку только с монитором ПК, только с часами и пейджером — как нужно именно вам.

## Железо

- Waveshare ESP32-S3-RLCD-4.2: модуль ESP32-S3-WROOM-1-N16R8 (16 МБ flash, 8 МБ PSRAM), экран 400×300 в 1 бит на пиксель, часы реального времени PCF85063A, датчик SHTC3, аудиокодек ES8311 с динамиком.
- Аккумулятор 18650 в держателе на плате. Без него плата работает от USB.
- Кабель USB Type-C. Внешний UART-адаптер не нужен: консоль работает через встроенный USB самого ESP32-S3.

Держатель батарейки для часов на плате пустой. Поэтому после отключения питания RTC теряет время. При сети Wi-Fi это не мешает: время подтягивается по NTP при старте. Если захотите поставить батарейку, берите только **аккумуляторную**: плата её заряжает, и обычная литиевая батарейка в этом держателе может потечь.

## Сборка и прошивка

Нужен [PlatformIO](https://platformio.org/): отдельный CLI или расширение для VS Code.

```bash
git clone git@github.com:alexex1993/esp32-s3-rlcd-clock.git
cd esp32-s3-rlcd-clock
cp example.env .env          # и заполните то, что нужно; без .env тоже соберётся

pio run                      # сборка
pio run -t upload            # сборка и прошивка по Type-C
pio device monitor           # консоль, 115200
pio run -t upload -t monitor # прошить и сразу открыть консоль
```

В проекте одно окружение, `esp32-s3-rlcd-4_2`, поэтому флаг `-e` не нужен. Из внешних библиотек используется только U8g2, PlatformIO скачает её сам.

Это сборка прошивки для платы. Серверная часть `rtss_api` собирается отдельно, компилятором Go, и живёт на игровом ПК — см. [«Сервер на ПК»](#сервер-на-пк).

## Режимы: какие экраны собирать

Четыре экрана — это четыре независимых режима, и какие из них попадут в прошивку, решает раздел `[modes]` в начале `platformio.ini`:

```ini
[modes]
clock = 1
news  = 1
pager = 1
pc    = 1
```

`1` — режим собирается, `0` — его в прошивке нет совсем: ни кода, ни запросов в сеть, ни места в круге переключения. Кнопка KEY ходит только по включённым экранам, а плата при старте включается на первом из них — то есть на часах, если режим часов включён, и на следующем, если нет.

| Режим | Что даёт |
|---|---|
| `clock` | Экран часов: время, дата, погода на улице, прогноз на 12 часов, закат, заряд. Вместе с ним выключается и загрузка погоды с Open-Meteo. |
| `news` | Экран «В МИРЕ» с заголовками. |
| `pager` | Экран «ПЕЙДЖЕР», соединение с Telegram через прокси и звуковой сигнал. |
| `pc` | Экран «КОМПЬЮТЕР» и опрос rtss_api по локальной сети. |

Примеры:

```ini
; только монитор игрового ПК
clock = 0
news  = 0
pager = 0
pc    = 1

; часы и пейджер, без новостей и ПК
clock = 1
news  = 0
pager = 1
pc    = 0
```

Несколько мелочей, о которых стоит знать:

- Режим и `.env` — разные вещи. Режим решает, есть ли экран в прошивке; `.env` решает, есть ли у него куда ходить. Включённый экран без своей строки в `.env` остаётся на месте и пишет, чего ему не хватает; выключенный не пишет ничего, потому что его нет.
- Если включён ровно один режим, KEY переключать не на что: кнопка ничего не делает, и в нижней строке экрана нет подсказки «KEY: …».
- Если включённых режимов нет вообще (все четыре нуля), прошивка всё равно собирается и запускается, а на экране появляется надпись **«ПУСТАЯ ПРОШИВКА»** и подсказка, где включить режимы. Плата при этом почти ничего не делает: в сеть не выходит, спит между пробуждениями.
- Время по NTP синхронизируется, пока включён хотя бы один режим и задан Wi-Fi, — часы в верхней строке есть на всех экранах, не только на часовом.
- После правки `platformio.ini` прошивку, как и после правки `.env`, нужно пересобрать и залить заново. При старте и по команде `?` плата печатает в консоль строку вида `modes: clock=1 news=0 pager=1 pc=0, KEY: ЧАСЫ -> ПЕЙДЖЕР -> ...`, так что всегда видно, что именно залито.

## Настройка: файл `.env`

Логины, пароли и токены лежат в файле `.env` в корне проекта. Он в `.gitignore` и в репозиторий не попадает. Готовый образец со всеми полями и пояснениями — [`example.env`](example.env): скопируйте его в `.env` и заполните нужные строки (пустая строка — то же самое, что её отсутствие). При сборке скрипт `scripts/env_flags.py` превращает эти значения в макросы препроцессора, то есть **после любого изменения `.env` прошивку нужно пересобрать и залить заново**.

```ini
SSID=имя-сети
PWD=пароль-wifi
NEWS_API=0123456789abcdef
TOKEN_BOT=123456789:AA...
SOCKS5_HOST=proxy.example.net
SOCKS5_PORT=1080
SOCKS5_USER=someone
SOCKS5_PASSWORD=secret
RTSS_HOST=192.168.0.100
RTSS_PORT=8099
```

Все поля необязательные. Прошивка собирается с любым их набором, а без поля отключается только то, что от него зависит:

| Чего нет в `.env` | Что пропадает |
|---|---|
| `SSID` / `PWD` | Вся работа с сетью: синхронизация по NTP, погода, новости, пейджер. Часы выставляются вручную из консоли. |
| `NEWS_API` | Экран новостей. Он остаётся, но пишет «нет ключа NEWS_API в .env». |
| `TOKEN_BOT` или `SOCKS5_HOST` | Экран пейджера. Он тоже остаётся и пишет, какой строки не хватает. |
| `SOCKS5_PORT` | Ничего: по умолчанию порт 1080. |
| `SOCKS5_USER` / `SOCKS5_PASSWORD` | Ничего: прокси будет использоваться без авторизации. |
| `RTSS_HOST` | Экран «КОМПЬЮТЕР». Он остаётся и пишет «нет RTSS_HOST в .env». |
| `RTSS_PORT` | Ничего: по умолчанию порт 8099, как у самого rtss_api. |

Значения можно брать в кавычки. `RTSS_HOST` можно записать и вместе с портом (`192.168.0.100:8099`), и просто скопировать адрес из браузера (`http://192.168.0.100:8099/`). Если при этом задан ещё и `RTSS_PORT`, используется он. Переменные окружения оболочки скрипт не читает намеренно: `PWD` в оболочке означает текущий каталог и незаметно стал бы паролем от Wi-Fi.

При сборке скрипт выводит, что он нашёл. Имя сети и адрес прокси печатаются полностью, чтобы опечатку было видно сразу. Пароли, ключ и токен печатаются только как «есть / нет».

### Погода

Погода берётся с [Open-Meteo](https://open-meteo.com/): там не нужны ни ключ, ни регистрация. Координаты заданы в `include/app.h` (сейчас это Братеево, Москва):

```c
#define WEATHER_LAT   "55.6386"
#define WEATHER_LON   "37.7561"
#define WEATHER_TZ    "Europe%2FMoscow"
```

Качество воздуха и УФ-индекс приходят отдельным запросом к [Air Quality API](https://open-meteo.com/en/docs/air-quality-api) того же Open-Meteo, тоже без ключа, по тем же координатам. На экране это «УФ 2» и «воздух 46». Воздух показан европейским индексом (European AQI): до 20 хорошо, 20–40 удовлетворительно, 40–60 средне, 60–80 плохо, 80–100 очень плохо, выше 100 крайне плохо.

Часовой пояс часов задаёт `TZ_OFFSET_SECONDS` в том же файле (сейчас UTC+3, без перехода на летнее время). Если вы переносите часы в другой город, поменяйте оба места.

### Новости

Нужен бесплатный ключ [NewsAPI](https://newsapi.org/). Одно открытие экрана расходует один запрос, а бесплатный тариф даёт 100 запросов в сутки.

Запрос намеренно не самый очевидный: `/v2/everything?domains=bbc.com,dw.com&language=ru`. Вариант `top-headlines?country=ru` у NewsAPI возвращает пустой список, а их русские источники `lenta` и `rbc` давно не обновляются.

### Telegram-пейджер

1. Создайте бота у [@BotFather](https://t.me/BotFather) и запишите токен в `TOKEN_BOT`.
2. Укажите SOCKS5-прокси в `SOCKS5_HOST` / `SOCKS5_PORT` (и `SOCKS5_USER` / `SOCKS5_PASSWORD`, если прокси требует авторизацию). **Прокси обязателен.** Прошивка писалась для сети, из которой `api.telegram.org` напрямую недоступен, поэтому прямого подключения в коде нет. Имя `api.telegram.org` отправляется прокси как доменное имя и разрешается на его стороне.
3. Напишите боту что-нибудь и откройте экран пейджера.

Соединение с Telegram идёт по TLS с проверкой сертификата. Прокси видит только зашифрованный трафик, токен бота через него в открытом виде не проходит.

Что стоит знать:

- При первом открытии пейджера после включения на экране появятся последние сообщения, накопившиеся у бота. Как только придёт первый ответ в реальном времени, Telegram считает их прочитанными. Поэтому после перезагрузки платы старые сообщения больше не показываются: они хранятся только в памяти часов.
- Звуковой сигнал раздаётся только на новые сообщения. Старые, показанные при открытии экрана, звука не вызывают.
- Сообщения без текста (стикер, фото без подписи) показываются как `[без текста]` с именем отправителя и временем.
- Бот читает личные сообщения и посты в каналах. В группе бот по умолчанию видит только команды, пока у него не выключен privacy mode в @BotFather.
- Если у бота настроен webhook, `getUpdates` работать не будет. Бот для часов лучше держать отдельным.
- Пока открыт пейджер, Wi-Fi остаётся включённым, и плата потребляет порядка 80 мА. Поэтому пейджер, в отличие от экрана новостей, сам на часы не возвращается: закройте его кнопкой KEY.

### Экран «КОМПЬЮТЕР»

Экран показывает телеметрию игрового ПК, которую отдаёт по сети **rtss_api** — небольшой HTTP-сервер для Windows, читающий общую память RivaTuner Statistics Server и MSI Afterburner. Он написан на Go, лежит в этом же репозитории в каталоге [`rtss_api/`](rtss_api/) и является частью проекта наравне с прошивкой: формат ответа у них общий, и меняются они вместе. Подробное описание сервера и его API — в [`rtss_api/README_RTSS.md`](rtss_api/README_RTSS.md).

#### Сервер на ПК

**Работает** сервер только под Windows: он читает общую память RTSS и Afterburner через `kernel32.dll`. А вот **собрать** его можно где угодно — на Windows, на Mac, на Linux. Go умеет кросс-компиляцию из коробки, и ниже разобрано, как именно.

##### Готовый бинарник

Если собирать не хочется, `rtss_api.exe` лежит в [релизах](https://github.com/alexex1993/esp32-s3-rlcd-clock/releases). Скачайте, положите на игровой ПК куда угодно и запустите.

Windows покажет предупреждение SmartScreen («Windows protected your PC» → *Подробнее* → *Выполнить в любом случае*): бинарник не подписан, а подпись стоит денег. Антивирус тоже может насторожиться — программа читает разделяемую память чужих процессов, и это ровно то, на что реагируют эвристики. Если такой расклад не устраивает, собирайте сами: зависимостей нет, это одна команда.

##### Сборка на Windows

Нужен [Go](https://go.dev/dl/) 1.23 или новее — и больше ничего. Внешних зависимостей у сервера нет, только стандартная библиотека, поэтому `go build` ничего не скачивает: ни `go get`, ни интернета, ни файла `go.sum` здесь не требуется.

```powershell
cd rtss_api
go build -o rtss_api.exe .
.\rtss_api.exe -addr :8099 -gpu 0
```

##### Кросс-компиляция с Mac или Linux

Две переменные окружения задают целевую платформу, всё остальное — та же команда:

```bash
cd rtss_api
GOOS=windows GOARCH=amd64 go build -o rtss_api.exe .
```

Получится настоящий `PE32+` для Windows, который остаётся скопировать на игровой ПК. Ни Windows SDK, ни mingw, ни виртуальной машины не нужно, и вот почему:

- **Тулчейн Go сам по себе кросс-компилятор.** Одна установка `go` собирает примерно под полсотни пар система-архитектура (полный список — `go tool dist list`) и пишет нужный формат файла: PE для Windows, ELF для Linux, Mach-O для macOS.
- **Библиотек целевой системы на сборочной машине не нужно.** Рантайм Go для Windows лежит исходниками прямо в тулчейне и компилируется под цель вместе с вашим кодом. Чистая Go-программа не линкуется с libc, так что искать на диске нечего.
- **Windows API связывается по имени в рантайме.** В `internal/winshm/winshm.go` это `syscall.NewLazyDLL("kernel32.dll")` и `.NewProc("OpenFileMappingW")`: в бинарник попадают только строки с именами, а поиск библиотеки и адреса функции происходит уже на Windows, при первом вызове. Во время сборки от `kernel32.dll` не нужно ничего.
- **Условие ровно одно — отсутствие cgo.** При кросс-сборке Go сам выставляет `CGO_ENABLED=0`, потому что C-кросс-компилятора в системе нет. Здесь это ничего не стоит: код использует только `syscall` и `unsafe`, а `import "C"` не встречается. Был бы cgo — понадобился бы mingw-w64 и `CC=x86_64-w64-mingw32-gcc`.

Отдельно стоит знать про одну «ошибку», которая ошибкой не является. На всех файлах сервера стоит `//go:build windows`, поэтому `go build` **без** `GOOS=windows` на Mac или Linux откажется собирать:

```
package rtss_api: build constraints exclude all Go files in .../rtss_api
```

Это не поломка сборки, а ровно то, что должно произойти: под не-Windows собирать тут нечего. Задайте `GOOS=windows`.

##### Флаги для сборки «на раздачу»

Если бинарник пойдёт куда-то дальше вашего диска, добавьте два флага:

```bash
GOOS=windows GOARCH=amd64 go build -trimpath -ldflags "-s -w" -o rtss_api.exe .
```

- `-trimpath` заменяет абсолютные пути сборочной машины на короткие вида `rtss_api/internal/...`. Без него внутри остаются строки вроде `C:/Users/вашеимя/...`, которые видны обычным `strings` — то есть имя пользователя уезжает вместе с файлом.
- `-ldflags "-s -w"` убирает таблицу символов и отладочную информацию DWARF: примерно 8,1 МБ превращаются в 6,3 МБ. На диагностику это не влияет — стек-трейсы при панике строятся по таблице `pclntab`, которую линковщик оставляет на месте. Теряется только возможность работать отладчиком вроде delve.

Сборка воспроизводима: одни и те же исходники, версия Go и флаги дают побайтово одинаковый файл. Единственное, что меняется само, — вшитый штамп git (`vcs.revision`, `vcs.time`, `vcs.modified`), поэтому сборки с разных коммитов или с незакоммиченными правками различаются, даже когда код одинаков.

##### Проверка результата

```bash
file rtss_api.exe             # PE32+ executable (console) x86-64, for MS Windows
go version rtss_api.exe       # какой версией Go собран
go version -m rtss_api.exe    # флаги сборки, GOOS/GOARCH, CGO_ENABLED, ревизия git
```

Последняя команда — самый быстрый способ убедиться, что `-trimpath` применился, а cgo выключен.

##### Флаги запуска

- `-addr` — адрес и порт, на которых слушать (по умолчанию `:8099`, тот же порт по умолчанию ждёт и прошивка);
- `-gpu` — номер видеокарты в Afterburner, если их несколько (по умолчанию `0`, первая).

Сервер стоит запускать при входе в систему (Планировщик заданий, «при входе пользователя»), чтобы он был на месте, когда часы к нему обратятся. Держать его запущенным почти ничего не стоит: своего опроса он не ведёт, каждый запрос — это несколько чтений уже отображённой в память области.

#### Что настроить

1. На ПК должны работать rtss_api, RTSS и MSI Afterburner. RTSS считает FPS, Afterburner снимает показания датчиков видеокарты и процессора, в том числе частоту видеопамяти.
2. В Afterburner на вкладке *Настройки → Мониторинг* отметьте датчики: температуру, загрузку, частоту ядра, частоту памяти (*Memory clock*), занятую видеопамять (*Memory usage*) и мощность GPU, температуру, загрузку и мощность CPU. Неотмеченных датчиков в общей памяти нет, и на часах вместо них будет `--`.
3. Разрешите в брандмауэре Windows входящие подключения к порту rtss_api (по умолчанию 8099), иначе часы до ПК не достучатся.
4. Запишите адрес ПК в `RTSS_HOST`, а порт в `RTSS_PORT`, если он не 8099. Адрес лучше закрепить за ПК в настройках роутера, чтобы он не менялся.

Сверху крупно текущий FPS. Под ним график FPS за последние 95 секунд: новые значения появляются справа, число в левом верхнем углу показывает, сколько FPS соответствует верху графика. Внизу три строки: **GPU** (загрузка, температура, частота ядра, мощность), **CPU** (общая загрузка по всем ядрам, температура, мощность) и **VMEM** (занятая видеопамять в гигабайтах, частота видеопамяти). Занятая видеопамять показывается с одним знаком после точки, остальные числа округлены до целых.

Что стоит знать:

- Часы берут данные с `/api/v1/metrics.bin`, держат с ПК одно постоянное соединение и запрашивают свежие цифры два раза в секунду. Каждый ответ добавляет на график одну точку. Afterburner по умолчанию сам обновляет датчики раз в секунду, так что чаще смысла нет.
- Когда игра не запущена, RTSS нечего считать: вместо FPS будет `--` и надпись «нет игры». Это не ошибка.
- Показание, которого у ПК нет (Afterburner не запущен, датчик не отмечен, процессор не сообщает мощность), показывается как `--`. Остальные при этом видны.
- График начинается заново при каждом открытии экрана. Там, где игры не было или ПК не отвечал, на графике пропуск.
- Часы читают только текущий формат rtss_api: 72-байтный ответ с частотой и занятой видеопамятью (описан в [`rtss_api/README_RTSS.md`](rtss_api/README_RTSS.md)). Ответы прежних версий, 68 байт без занятой видеопамяти и 76 байт с 1% low, часы не принимают: на экране будет «это не rtss_api», а в консоли сообщение, что rtss_api нужно обновить.
- Если ПК перестал отвечать, через 3 секунды цифры пропадают, и экран пишет причину. Когда ПК снова доступен, соединение восстанавливается само. Если пропал Wi-Fi, часы тоже переподключаются к сети сами.
- Как и пейджер, этот экран сам на часы не возвращается, и Wi-Fi всё время, пока он открыт, остаётся включённым. Закройте его кнопкой KEY.

## Кнопка KEY

Каждое нажатие переключает экраны по кругу: **часы → новости → пейджер → компьютер → часы**. В круге только те экраны, которые включены в `[modes]` (см. [«Режимы»](#режимы-какие-экраны-собирать)); если включён один, кнопка ничего не делает.

- Экран новостей при открытии загружает заголовки и через 45 секунд без нажатий сам возвращается на часы.
- Пейджер при открытии подключается к Telegram и держит соединение, пока вы не нажмёте KEY ещё раз.
- Экран «КОМПЬЮТЕР» так же держит соединение с ПК до следующего нажатия. При переходе на него с пейджера Wi-Fi не отключается, поэтому ждать подключения к сети второй раз не нужно.
- Пока идёт подключение, экран сразу показывает «загружаю новости...» или «подключаюсь...». Это занимает несколько секунд, в это время изображение не обновляется.

Ни новости, ни Telegram, ни данные с ПК не загружаются по таймеру. Если никто не нажимает кнопку, на них не тратится ни трафик, ни заряд.

## Консоль

Консоль доступна через `pio device monitor` (115200). Каждая команда вводится отдельной строкой:

| Команда | Что делает |
|---|---|
| `T2026-09-09 21:30:00` | Выставить часы вручную (местное время). |
| `N` | Синхронизировать время и погоду прямо сейчас. Новости эта команда не трогает. Есть в прошивке, только если задан Wi-Fi. |
| `P` | Один раз прочитать Telegram и поставить 👀 на прочитанное, после чего выключить Wi-Fi. Нужна, чтобы по логу понять, что не так: прокси, логин к нему или токен. Не работает, пока открыт экран пейджера. |
| `B` | Проверить динамик коротким сигналом. Другого способа проверить звук нет. |
| `?` | Состояние: RTC, заряд, температура и влажность в комнате по датчику SHTC3 (на экран она не выводится), погода на улице с качеством воздуха и УФ-индексом, возраст прогноза, закат, число заголовков и сообщений, прокси, связь с ПК и её ошибка, время до следующей синхронизации. Последней строкой — включённые режимы и порядок экранов. |

## Как это работает

- **Wi-Fi включается редко.** Раз в 30 минут плата подключается к сети, сверяет время по NTP, загружает погоду и качество воздуха и отключается. Если попытка не удалась, следующая будет через минуту. Пока открыт пейджер или экран компьютера, плановая синхронизация откладывается, чтобы не рвать их соединение.
- **Время.** RTC хранит местное время. При включении плата пробует источники по порядку: NTP, затем время сборки прошивки, затем ручной ввод из консоли. Время сборки лишь заполняет экран чем-то правдоподобным: на нём остаётся надпись «ЧАСЫ НЕ ЗАДАНЫ», пока время не придёт из NTP или консоли.
- **Экран обновляется только при изменениях.** На часах это раз в секунду, на экранах со списками раз в минуту (там меняется только время в верхней строке), на экране компьютера с каждым новым ответом ПК, то есть два раза в секунду.
- **Аккумулятор.** Напряжение 18650 измеряется через делитель на GPIO4, процент считается по кривой разряда Li-ion, а не по прямой. При заряде 10% и ниже внизу экрана слева появляется «НИЗКИЙ ЗАРЯД».
- **Текст.** У шрифтов экрана есть только латиница и кириллица. Кавычки-ёлочки, длинные тире, многоточия, эмодзи и прочие символы из новостей и сообщений перед выводом заменяются на то, что шрифт умеет рисовать (`«»` → `"`, `—` → `-`, `…` → `...`, эмодзи удаляются).
- **Без JSON-библиотек и без выделения памяти.** Ответы серверов разбираются потоком через небольшой буфер, так что размер ответа не важен.

## Если что-то не работает

**Экран пустой.** Проверьте, что прошивка действительно залилась, и откройте консоль: при старте плата пишет, какие устройства на шине ответили. Если прошивка не заливается (`Wrong boot mode detected`, `No serial data received`), переведите плату в режим загрузки вручную. Кнопки RESET на этой плате нет, поэтому порядок такой: зажмите BOOT, коротко нажмите PWR (или переподключите USB-кабель), отпустите BOOT и запустите `pio run -t upload`.

**На экране «ПУСТАЯ ПРОШИВКА».** В `platformio.ini` все четыре режима выключены. Поставьте нужным `1` в разделе `[modes]` и пересоберите прошивку.

**В консоли ничего нет.** Консоль появляется только после того, как компьютер распознал USB-устройство. Первые строки после сброса можно пропустить, поэтому отправьте `?`.

**На экране «ЧАСЫ НЕ ЗАДАНЫ».** Не удалось получить время ни по NTP, ни из консоли. Проверьте `SSID` / `PWD` в `.env` (после правки файла прошивку нужно пересобрать) или выставьте время командой `T`.

**Пейджер показывает ошибку.** Экран сообщает, на каком шаге оборвалась цепочка:

| Надпись | Что проверить |
|---|---|
| `нет TOKEN_BOT в .env` / `нет SOCKS5_HOST в .env` | Прошивка собрана без этой строки в `.env`. |
| `прокси недоступен` | Адрес и порт прокси, логин и пароль к нему, работает ли прокси вообще. |
| `нет защищённого канала` | TLS-соединение через прокси не установилось. Прокси пропускает соединение, но не до Telegram. |
| `сертификат отклонён` | Сертификат `api.telegram.org` не прошёл проверку по корневым сертификатам ESP-IDF: соединение где-то по пути подменяется. |
| `телеграм отклонил запрос` | Неверный токен или у бота настроен webhook. Точный ответ сервера будет в логе после команды `P`. |
| `телеграм не ответил` | Соединение есть, но ответ не пришёл. Обычно это медленный или нестабильный прокси. |
| `нет сообщений` | Всё работает, просто боту ещё никто не писал. |

Во всех случаях с ошибкой начните с команды `P` в консоли: в логе будет видно, на каком шаге и с каким кодом всё оборвалось.

**Экран «КОМПЬЮТЕР» показывает ошибку.** Надпись в середине экрана говорит, на чём остановилось подключение:

| Надпись | Что проверить |
|---|---|
| `нет RTSS_HOST в .env` | Прошивка собрана без этой строки в `.env`. |
| `нет Wi-Fi` | Часы не подключены к сети. Переподключение идёт само. |
| `адрес ПК не найден` | В `RTSS_HOST` записано имя, которое не удалось разрешить. Укажите IP-адрес. |
| `ПК не отвечает` | ПК выключен или спит, у него сменился адрес, или брандмауэр Windows не пропускает порт 8099. |
| `rtss_api не запущен` | ПК в сети, но на этом порту никто не слушает. Запустите rtss_api или проверьте `RTSS_PORT`. |
| `ПК не ответил` | Соединение есть, но ответа нет дольше 2 секунд. |
| `rtss_api ответил ошибкой` / `это не rtss_api` | На этом адресе и порту отвечает что-то другое или несовместимая версия rtss_api. |

Если FPS показывается, а все показания GPU и CPU `--`, значит, не запущен Afterburner или в нём не отмечены датчики. Подробности ошибки подключения печатаются в консоль, а `?` показывает состояние связи с ПК.

**Нет звука.** Отправьте `B`. Если в ответ пришло `ES8311 MISSING`, кодек не отвечает по I2C. Если кодек на месте, а звука нет, учтите: звуковая часть прошивки собрана по референсной последовательности Espressif, но на живой плате ещё не проверялась.
